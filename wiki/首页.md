# API Workbench

**本地优先的 AI 接口兼容性与诊断桌面工作台(Windows / macOS)。**

English: [Home](Home)

## 这是什么

给"对接 AI 接口的开发者"用的诊断工具——不是聊天软件:

**配置服务商 → 同步模型 → 发送测试请求 → 分析失败原因 → 导出脱敏报告**

## 功能矩阵

| 领域 | 能力 |
| --- | --- |
| 协议 | OpenAI Chat Completions · Anthropic Messages · OpenAI Responses |
| 请求测试 | 非流式 + 真增量流式(跨块 UTF-8 正确)、取消、超时、参数最小化 |
| 工具调用 | 固定无副作用示例工具、白名单强制、每步可视化(参数/执行/回传) |
| 对比 | 同一提示词并发发给 ≤5 家:状态 / 耗时 / TTFB / 首字 / usage / 最快徽章 |
| 性能 | 用户主动启动、并发 ≤4、请求与时间上限、遇 429 立即停、零自动重试 |
| 诊断 | 事实 / 按可能性排序的原因 / 建议步骤 / 不确定性声明,保留原始证据 |
| 报告 | Markdown / JSON 导出,默认脱敏,脱敏 curl 复现示例 |
| 配置 | JSON 导出/导入(设计上无密钥),逐条校验 |
| 密钥 | 系统安全存储(Keychain / DPAPI),不可用时仅会话内存并明示 |
| 安全 | 渲染进程沙箱、CSP `connect-src 'none'`、网络全在主进程、TLS 不提供关闭选项 |

## 快速开始

1. 概览页一键启动内置模拟服务(无需真实 Key)
2. 服务商页 → 添加 `http://127.0.0.1:<端口>` + 任意 `sk-mock` 开头的密钥
3. 模型页 → 同步
4. 请求测试页 → 试 `mock-chat-mini`,或故障注入模型:`mock-500`、`mock-hang`、`mock-break`
5. 诊断历史页 → 导出脱敏报告

## 质量状态
